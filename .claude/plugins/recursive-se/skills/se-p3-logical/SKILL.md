# P3 — Logical Decomposition

> 本阶段唯一核心问题：**为了满足需求，逻辑上必须发生什么？**
> 逻辑功能**不是**模块/服务/类——它是"必须发生的转换"，谁来承担是 P4 的事。

## 六问

### P3-Q1 逻辑上必须执行哪些功能？

列出逻辑功能清单（编号 LF-x），每个：输入 → 转换 → 输出。
要求：每条 LF 能回引服务的 REQ；每个 REQ 至少有一条 LF 承载（No Orphan 检查）。

### P3-Q2 功能之间有什么时序、条件和依赖？

触发条件 / 先后顺序 / 并行关系 / 数据依赖。可用文本时序图。

### P3-Q3 系统有哪些逻辑状态或运行模式？

状态清单 + 状态迁移（事件→迁移→目标状态）。
要求：异常/降级/维护态也算正式状态，不许只有"正常运行"一种。

### P3-Q4 什么信息/物料/能量必须流动？

流的清单：源→携带内容→目的地→频率/量级→丢失后果。

### P3-Q5 失败或异常时逻辑上必须怎样响应？

每个关键失败：检测（怎么知道坏了）→ 响应（逻辑上做什么）→ 后果边界（坏到哪为止）。
反例（禁）：`失败时系统应保持稳定`——无检测无动作无边界。

### P3-Q6 逻辑分解产生了哪些派生需求？

分解过程中发现的新需求（如"LF3 要求 LF1 的输出延迟 ≤X"）→ **回写 P2 台账**（REQ-DRV-x），保持台账单一权威。

## 输出规范

`docs/SE/<soi-name>/P3-logical.md`：LF 清单（含 REQ 回引）/ 时序 / 状态迁移表 / 流 / 失败响应 / 派生需求回写记录。

## Exit Gate

每个 REQ 有 LF 承载？每个 LF 可回引 REQ？异常路径有检测-响应-边界？派生需求已回写 P2？
