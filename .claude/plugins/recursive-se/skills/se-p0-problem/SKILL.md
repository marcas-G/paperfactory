# P0 — Problem Definition

> 本阶段唯一核心问题：**现实世界到底有什么问题？为什么值得解决？**
> 只描述现实问题。**不出现**模块名、数据库、框架、类名——那些是解决方案。

## 依次回答五问（每问先给答案再自检反例）

### P0-Q1 谁在什么情况下遇到了什么核心问题？

模板：`[问题主体] 在 [具体场景] 下，由于 [现实原因/现状]，难以/无法 [原本希望完成的行为]。`
要求：一个 Problem Statement 只描述一个核心问题。

### P0-Q2 造成什么实质后果？

模板：`该问题导致 [明确损失]，主要影响 [对象/过程]。`
要求：后果必须可归入——成本 / 时间 / 风险 / 可靠性 / 错误率 / 资源浪费 / 业务损失。
反例（禁）：`很严重，影响用户体验`——不可分析。

### P0-Q3 为什么现有方式无法充分解决？

模板：`当前通常通过 [现有方式] 处理，但在 [条件] 下，由于 [具体机制]，仍然无法解决 [问题]。`
要求：必须给出 现有机制 + 失效条件 + 失效原因 三件套。

### P0-Q4 什么现实结果意味着问题得到解决？

模板：`当问题得到解决后，[主体] 应能够 [结果]，而不再需要 [当前被迫采取的行为]。`
要求：描述 **Outcome（现实变化）**，不是 Feature（系统功能）。
反例（禁）：`系统应该支持 checkpoint`——这是方案不是结果。

### P0-Q5 本轮工程明确解决什么，不解决什么？

In Scope / Out of Scope 各列清单。
要求：Scope 必须具体到能用于**拒绝后续 Scope Creep**。

## 输出规范

写入 `docs/SE/<soi-name>/P0-problem.md`，含五问答案 + Exit Gate 自查表（谁遇到问题/问题是什么/什么后果/现有为何不够/解决后变化/边界）。

## Exit Gate（六问全过才准进 P1）

谁遇到问题？问题是什么？造成什么后果？为什么现有办法不够？解决后现实结果是什么？问题边界在哪里？
