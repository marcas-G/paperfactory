# P4 — Architecture Design

> 本阶段唯一核心问题：**哪些系统元素承担 P3 的逻辑责任？**

## 七问

### P4-Q1 需要哪些下一级系统元素？

元素清单（编号 E-x，命名按职责不按技术）。
要求：每个元素的存在理由 = 它承担的 LF 集合（No Orphan）。

### P4-Q2 每项逻辑责任由谁主要承担？

LF × E 的分配表。**每行有且只有一个主要承担者**（Rule 3: Single Primary Ownership）；
可有协作者但责任唯一——出问题知道找谁。

### P4-Q3 每个元素负责什么、不负责什么？

每个 E 的职责边界（Responsibility / Not responsibility）。
反例（禁）：`E3 负责通用功能`——"通用"= 边界不清。

### P4-Q4 关键状态、资源或资产由谁权威拥有？

每个关键状态/资源：**唯一权威拥有者**（谁说是就是），其他持有的是副本/缓存。
要求：无权威拥有者的状态 = 一致性隐患，必须在此消灭。

### P4-Q5 元素之间通过什么接口交互？

每个接口：双方 / 方向 / 内容 / 契约要点（同步异步、失败语义）。
要求：接口是两元素**共同**的合约——单方面改接口 = 破坏合约。

### P4-Q6 系统级流程由谁协调？

跨元素的流程（谁发起、谁编排、谁裁决冲突）——**必须有明确协调者**，不允许"大家一起商量"。

### P4-Q7 为什么选择这种架构，而不是其他方案？

至少列 2 个被否决的替代方案 + 否决理由（轻量 ADR 表：决策/理由/替代）。
要求：没有替代方案的架构选择不是决策，是默认——Rule 4: No Hidden Design。

## 输出规范

`docs/SE/<soi-name>/P4-architecture.md`：元素清单 / LF×E 分配表 / 职责边界 / 权威拥有表 / 接口表 / 协调机制 / ADR 表。

## ⚠️ P4 结束 ≠ 架构结束

**P4 是递归分叉点**：对每个下一级元素执行 se-recursion-check——够简单则进 P5，否则提升为新 SoI 重走 P0-P4。
