# P1 — Stakeholder & Operational Context

> 本阶段唯一核心问题：**谁会怎样与当前 SoI 交互，SoI 处于什么外部环境？**
> 开始描述系统与现实的关系，但**仍不设计系统内部**。

## 五问

### P1-Q1 哪些 Stakeholder 对当前 SoI 有真实关切？

每个干系人：`角色 / Concern（具体关切）/ 影响或被影响的方式`。
要求：Concern 必须具体到能生成需求；列到"会影响设计决策"的粒度为止。

### P1-Q2 当前 SoI 的边界以及外部实体是什么？

模板：SoI 包含什么 / 不包含什么 / 与哪些外部实体交互（各交互什么）。
要求：边界两侧的归属必须明确——**"边界外但必须为它负责"的东西要显式列出**。

### P1-Q3 正常运行场景是什么？

用序号步骤描述典型使用流（谁、做什么、系统响应什么）。
要求：覆盖主要干系人的主路径；场景里不出现内部实现。

### P1-Q4 关键异常运行场景是什么？

至少覆盖：外部依赖失效 / 部分能力降级 / 恶劣条件 / 中断-恢复。
要求：异常场景是后续 P2 质量/韧性需求的直接来源，不许跳过。

### P1-Q5 当前 SoI 必须适应什么运行环境？

物理/网络/软件/组织环境；干扰因素（哪些外部波动必须容忍）。

## 输出规范

写入 `docs/SE/<soi-name>/P1-stakeholders.md`：干系人表 + 边界图（文本树）+ 场景编号（C1/C2/…，P2 需求将回引这些编号）+ Exit Gate 自查。

## Exit Gate

谁影响系统？边界内外各是什么？正常/异常主场景？运行环境与干扰？每条场景可回引？
