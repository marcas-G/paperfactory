# P6 — Implementation

> 本阶段唯一核心问题：**实际产物是否忠实实现了既定设计？**
> 注意方向：P6 检查"实现 vs 设计"，不是检查"设计 vs 需求"（那是 P7）。

## 四问

### P6-Q1 实际产物对应哪个 Design Element？

设计→产物的映射表（每个 P4/P5 元素 → 文件/模块/设备/文档位置）。
要求：**无主产物=规格外实现**——技术上可存在，工程上不算交付，要么补设计要么删。

### P6-Q2 实现是否满足 Contract 和 Invariant？

逐条对照 P5 的接口五件套与不变量：满足 / 偏差 / 未实现。
**偏差必须显式登记，不许静默**。

### P6-Q3 实施过程中有没有突破既定系统边界？

实现里是否出现了 P4 职责表之外的调用/依赖/数据流（跨元素直捅内部、绕过权威拥有者）。
**边界突破是架构腐化的第一步**，发现即修或改架构（走 ADR，不许偷偷改）。

### P6-Q4 实施过程中是否出现新的设计决策？

写代码时被迫做的设计决定（数据结构、重试策略、并发模型…）→ 回写为轻量 ADR。
Rule 4 No Hidden Design：**藏在代码里的设计决策不算存在**。

## 输出规范

`docs/SE/<soi-name>/P6-implementation.md`：映射表 + 偏差清单（B-x 编号，各挂 REQ/纠正措施）+ 新增 ADR 回写。

## Exit Gate

每元素有产物映射？偏差全登记（无静默）？边界突破=0 或已修？新决策已 ADR 化？
