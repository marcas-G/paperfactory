# P2 — System Requirements

> 阶段唯一问题：**系统必须具备什么可验证的能力和性质？**
> 每条 REQ = 能力一句话 + 验证标准（Criterion）。状态：✅ 已实现有证据 / 🟡 部分 / ❌ 未实现。
> 验证标准在 P7 兑现为证据；❌/🟡 即路线图。

## R 组 — 研究能力（服务 C1）

| REQ | 能力 | 验证标准 | 状态 |
|---|---|---|---|
| REQ-R1 | 给定研究问题，检索真实学术文献（全学科优先、arXiv 兜底） | 产出条目含可点开来源 URL；网络断源时降级不崩溃 | ✅ |
| REQ-R2 | LLM 逐篇评估文献相关性，低相关拒入知识库 | 错配领域文献 0 条入库（实测：CS 论文对教育心理学问题全被滤） | ✅ |
| REQ-R3 | 基于文献生成结构化假设（含可证伪条件） | 假设对象含 statement + falsificationCondition | ✅ |
| REQ-R4 | 设计并执行计算实验（LLM 生成协议 → 沙箱执行） | 实验产出数值输出；执行失败记为 NEUTRAL 低强度证据 | ✅ |
| REQ-R5 | 汇总证据生成 Markdown 报告，引用仅限已入库来源 | 报告引用 ⊆ 知识库条目；无来源引用视为缺陷 | 🟡（引用约束未程序化校验） |
| REQ-R6 | 研究运行全程事件流实时可见 | 每阶段/工具调用产生事件；web/TUI 均可渲染 | ✅ |

## G 组 — 治理（宪法三公理的落地）

| REQ | 能力 | 验证标准 | 状态 |
|---|---|---|---|
| REQ-G1 | manual 模式关键阶段人工审批（放行/修改/拒绝） | 审批挂起时研究暂停；决策事件入账 | 🟡（链路在，端到端实测缺） |
| REQ-G2 | 状态变更仅经治理链（LLM 提议、系统裁决） | 无 set_status 直改路径；变更伴随 Domain Event | ✅（对象层）；🟡（事件→对象投影未闭环） |
| REQ-G3 | 证据链可下钻：结论→证据→实验→文献 | 每层对象携带上游引用 ID；API 提供 chain 端点 | 🟡（API 在，前端下钻未通） |
| REQ-G4 | LLM 断线不摧毁运行（重试+降级） | 断线重试 1 次；评估失败降级原文摘要；报告失败可重跑 | ✅ |

## REC 组 — 恢复（服务 C2，当前最大缺口）

| REQ | 能力 | 验证标准 | 状态 |
|---|---|---|---|
| REQ-REC1 | 事件账本持久化：append-only、seq 单调 | 杀进程重启后 SSE 按 lastEventId 补发全部历史 | ✅（实测 19 事件补发） |
| REQ-REC2 | 研究对象（项目/假设/证据/报告）从事件账本投影重建 | 无 DATABASE_URL 重启后对象在场，与账本一致 | ❌ **核心缺口：有账本无投影** |
| REQ-REC3 | PG 持久化模式（多端共享状态） | DATABASE_URL 设置时走 Pg 存储；多端看到同一状态 | 🟡（PgObjectStore 在，未端到端实测） |
| REQ-REC4 | 研究任务断点续跑（非整轮重跑） | 中断后 resume 从未完成阶段继续 | ❌ |
| REQ-REC5 | 长循环预算刹车（步数/超时/输出截断） | 超预算强制收卷不失控烧钱 | 🟡（maxIterations 在；超时/截断不齐） |
