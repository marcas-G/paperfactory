# P3 — Logical Decomposition

> 阶段唯一问题：**为了满足需求，逻辑上必须发生什么？**（只谈逻辑步骤，不绑定技术元素）

## L1 研究循环（主逻辑，服务 REQ-R*）

```text
L1.1 观察研究状态    当前问题/缺口/假设/证据处于什么状态？
L1.2 识别关键不确定性 当前最值得消除的不确定是什么？（宪法 §15.7）
L1.3 选择研究动作    在合法动作集中选一个（文献调研/假设生成/实验/汇总）
L1.4 组织上下文      本动作需要看到什么信息？（宪法 §19：编译而非堆积）
L1.5 认知执行        LLM 在指定认知模式下执行（EXPLORE/FRAME/...）
L1.6 能力调用        调用具体能力（检索/计算/写作）获得结构化观测
L1.7 评估            观测是否支持状态变更？（Gate：确定性优先，语义必要才 LLM）
L1.8 状态演进        变更研究状态并产生不可变事件
      ↻ 回到 L1.1，直到停止条件（预算耗尽/无合法动作/人工停止）
```

## L2 治理逻辑（服务 REQ-G*）

```text
L2.1 提议-裁决分离   一切状态变更由 LLM 提议、确定性代码裁决
L2.2 审批挂起        manual 模式下关键转换暂停等待人工决策（可持久化）
L2.3 证据绑定        结论必须携带证据引用；无证据的 prose 不改变状态
L2.4 失败分类        Runtime 失败（可重试）与科研失败（进分析流程）分流
```

## L3 恢复逻辑（服务 REQ-REC*）

```text
L3.1 记账            每个有意义的行为先落不可变账本（seq 单调）
L3.2 事件重放        任何消费者可从任意 seq 续传（断线/重启同语义）
L3.3 状态重建        当前状态 = 初始状态 × 账本重放（投影）
L3.4 断点续跑        运行中断后从未完成的逻辑步骤继续（依赖 L3.3）
```

## L4 多端逻辑（服务 REQ-M*）

```text
L4.1 命令            客户端发起动作，立即获得受理凭据（runId），不等结果
L4.2 订阅            客户端订阅唯一事件流，一切进度由事件驱动渲染
L4.3 查询            客户端按需拉取当前状态（资源端点，幂等）
L4.4 契约            端点与事件目录唯一权威定义，客户端代码生成
```
