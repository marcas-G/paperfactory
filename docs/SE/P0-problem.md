# P0 — Problem Definition

> 阶段唯一问题：**现实中为什么需要 PaperFactory？**（描述现实问题，不出现任何软件方案）

## P0-Q1 谁在什么情况下遇到了什么阻碍？

```text
研究人员（含研究生、独立研究者、跨学科工程师）在开展开放式研究时，
由于 研究过程包含大量重复性认知劳动——文献追踪、假设管理、实验记录、
证据核对、报告撰写——且这些劳动分散在聊天窗口、笔记、代码脚本、
电子表格等多个互不联通的工具中，
难以 保持一个连贯、可追溯、可中断可恢复的研究状态，
也难以 把主要精力留给真正需要人类判断的环节。
```

## P0-Q2 造成什么后果？

```text
该问题导致：
- 时间：每次回到研究课题都要花 30 分钟以上重建上下文；
- 成本：文献结论散落多处，重复检索、重复阅读已成常态；
- 风险：口头/聊天里的"结论"缺乏证据链，写报告时无法追溯依据，
  出错后无法定位是哪一步的证据出了问题；
- 可靠性：长时研究任务一旦中断（进程退出、注意力切换、假期间隔），
  已完成阶段的可复用性依赖个人记忆。
```

## P0-Q3 现有解决方式为什么不足？

```text
当前通常通过 ①对话式 AI 助手 ②文献管理软件 ③实验记录本/Wiki
④自写脚本流水线 处理：
- ① 可以干活但状态即聊天记录：无法结构化恢复、无法审计"当时凭什么下结论"；
- ②③ 只管资料不管推理过程，与研究状态脱节；
- ④ 能自动化但一中断就重跑，且无治理（脚本自己改自己"成功"的判据）。
失效的共同机制：研究状态没有独立于对话/脚本的、结构化的、持久的承载。
```

## P0-Q4 解决后现实结果的变化？

```text
当问题得到解决后，研究人员应能够：
- 在任意时刻离开并在之后回到"最近一次有效研究状态"继续，
  而无需 重读全部聊天记录重建上下文；
- 对任何一条研究结论追问"依据是什么"并得到可点开的证据，
  而无需 凭记忆翻找文献和实验输出；
- 把例行认知劳动交给可治理的自动化，
  而无需 把精力消耗在"记得做了什么、做到哪了"上。
```

## P0-Q5 边界

```text
In Scope:
- 研究状态的结构化承载与演进（问题/缺口/假设/证据/结论）
- 长任务的中断-恢复与可追溯
- 例行认知劳动的受治理自动化（LLM 提议、系统裁决）
- 多端访问（web/终端，及未来移动端）

Out of Scope:
- 替代人类的研究判断（选题品味、创造性假设的最终裁决权）
- 实验室物理设备管理 / 临床试验合规
- 论文排版出版流程（LaTeX 编译仅作为能力挂接点）
- 通用聊天机器人用途
```

## P0 Exit Gate 自查

| 问 | 答 |
|---|---|
| 谁遇到问题 | 开展开放式研究的人员 |
| 问题是什么 | 研究状态无结构化持久承载，认知劳动重复且不可追溯 |
| 什么后果 | 时间/成本/风险/可靠性四类损失 |
| 现有方式为何不足 | 聊天/文献库/脚本各自承载片段，状态本身无人承载 |
| 解决后变化 | 可离开-可回来；结论可追证；例行劳动可托付 |
| 边界 | 见 In/Out Scope |
